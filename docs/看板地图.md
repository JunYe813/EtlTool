# 看板地图（Streamlit 实现对照）

启动：`streamlit run app/dashboard.py`

## 结构

```
app/
├── dashboard.py      入口：全局筛选器 + st.navigation 多页导航
├── db.py             共享数据访问层（连接 / 缓存查询 / 筛选器 / 列名转换）
└── pages/
    ├── sales_overview.py      1 销售总览
    ├── product_analysis.py    2 商品分析
    ├── seller_region.py       3 卖家与地区
    ├── user_analysis.py       4 用户分析
    └── fulfillment.py         5 履约漏斗
```

## 全局筛选器（侧边栏，5 个页面共享）

在 `dashboard.py` 里于 `navigation.run()` **之前**渲染，结果写入 `st.session_state["filters"]`。

| 筛选项 | 说明 |
|---|---|
| 购买日期 | 默认取数据实际范围 `2016-09-04 ~ 2018-09-03`（**不用** `datetime.now()`，数据是 2016-2018 的） |
| 英文类目 | 多选，留空 = 全部 |
| 卖家州 | 多选，留空 = 全部 |
| 留存最小 cohort 规模 | 默认 20，过滤 `cohort_size = 1` 导致 100% 留存的噪声 |
| 刷新数据缓存 | 清 `st.cache_data`；ADS 重跑后缓存不会自动失效 |

## 1 · 销售总览

数据源：`ads_sale_overview_daily`

- Metric：GMV / 有效订单数 / 客单价 / 去重买家数 / 明细行数
- 趋势：日或月粒度的 GMV 面积图（叠加移动平均虚线）+ 有效订单数柱状图
- 明细表 + CSV 下载

**口径要点**
- 客单价 = 区间 GMV ÷ 区间订单数，**现算**；不对日客单价求平均
- 去重买家从 `dwd_order` 现算，**不用** `SUM(日表 buyer_cnt)`
  （跨天复购会重复计数：实测 97,272 vs 真实 94,986）

## 2 · 商品分析

数据源：`v_sale_daily_category` + `dwd_order_detail` + `ads_top_product`

- 类目 GMV 占比环形图（Top N + 「其他」归并）
- 类目 GMV Top15 横向柱状图
- Top 类目月度趋势（多选类目折线）
- 热销商品 TopN 表（可选 N）
- 每日 Top10 商品榜（来自 ADS 预聚合表，可任选日期）

**口径要点**
- 占比在筛选后的数据集上现算，不直接用视图里预算好的百分比
  （否则按日期筛选后分母仍是全周期总额，占比不等于 100%）

## 3 · 卖家与地区

数据源：`v_sale_daily_seller_state` + `v_sale_daily_buyer_state` + `ads_top_seller`

- Metric：卖家州数 / 买家州数 / 两侧 GMV 合计
- 卖家州 GMV 对比柱状图
- 买家州 GMV 对比柱状图
- 卖家 TopN 表（区间现算）+ 有成交卖家总数
- 全周期卖家榜（来自 `ads_top_seller`，不受日期筛选影响）

**口径要点**
- 两个 GMV 合计相等是正常的（同一批有效订单换个维度看）
- **订单数跨州不可相加**：一单可含多个卖家州的商品，会被重复计数

## 4 · 用户分析

数据源：`ads_user_repeat_overall` + `v_retention_curve` + `ads_user_repeat_monthly`

- 复购概览：购买买家数 / 复购买家数 / 复购率 / 人均订单数（全周期）
- 各留存窗口 metric（7/30/60/90 日）
- Cohort 留存曲线（按留存窗口分色）
- 加权留存率柱状图（`Σ留存数 ÷ Σcohort规模`，比「留存率的平均」更准确）
- 复购率月度趋势（红点标注右删失的 cohort）+ 明细表

**口径要点**
- 留存 = 首购后**第 1~N 日内**再次购买（不含首购当天）
- 自动用 `is_complete` 剔除观察窗未满的 cohort（右删失）
- 自动用 `cohort_size >= 20` 剔除小样本噪声
- 留存窗口结束时提示可调低 cohort 规模门槛

## 5 · 履约漏斗

数据源：`v_fulfillment_funnel` + `ads_fulfillment_monthly`

- 四阶段 metric：下单 / 支付审批 / 交承运 / 客户签收（含占下单比）
- 取消订单数、未签收订单、整体签收率
- 漏斗横向柱状图（带数值标签）+ 各环节流失明细
- 履约时长：平均审批时长（小时）/ 发货时长 / 签收时长
- 月度趋势：各阶段订单数折线 + 平均签收时长折线
- 月度明细表

**口径要点**
- 漏斗使用**全量订单**，不过滤有效订单 ——
  取消/未支付正是漏斗流失的来源，过滤掉会把漏斗削平
- 汇总时长**按订单量加权**，不能用 `AVG(月度均值)`
  （未加权 14.31 天 vs 加权正确值 12.50 天）

## 开发提示

改动看板后跑一遍冒烟测试（无头运行，不需要浏览器）：

```bash
python scripts/check_dashboard.py
```

它会用 Streamlit 官方 `AppTest` 依次执行入口和 5 个页面，捕获异常并统计渲染出的
metric / 图表 / 表格数量。

**已知环境坑**
- `psycopg2` 读回的 `DATE` 列在 pandas 里是 `object`（元素为 `datetime.date`），
  直接 `.dt` 访问会报 `Can only use .dt accessor with datetimelike values`。
  已在 `db.query()` 里统一转成 `datetime64`。
- Streamlit 元素类型名是 `vega_lite_chart`（不是 `arrow_vega_lite_chart`）。
